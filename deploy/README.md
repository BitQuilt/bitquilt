# The public tracker's host

One small virtual machine with Docker (two cores and two gigabytes are plenty to start), reached at `tracker.bitquilt.org`, running the hosted tracker behind Caddy. The site is not here: it is a static deployment of `site/` on Vercel at `bitquilt.org`, where the domain's DNS lives. What this folder holds: the compose file (the tracker built from this repository, and Caddy), the Caddyfile (TLS for the name, every request to the tracker, streaming left alone), and the names of the environment the tracker reads.

In order, on a fresh host:

1. In Vercel's DNS for bitquilt.org, an `A` record `tracker` pointing at the host's address. Caddy fetches the certificate once the name resolves.
2. Docker installed (`curl -fsSL https://get.docker.com | sh`), and the repository cloned with a read-only deploy key or a fine-grained token, since it is private: `git clone https://github.com/BitQuilt/bitquilt.git /srv/bitquilt`.
3. `cp deploy/env.example deploy/.env` and fill it in: the key secret made once with `openssl rand -hex 32` and kept in two places, the salt, the maintainers' address, the coin's parameters from `docs/LAUNCH.md` with a genesis a day or two ahead. The file stays on the host.
4. `docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build`, then `curl -s https://tracker.bitquilt.org/.well-known/quilt` answers with `"hosted": true` and the coin's parameters.
5. Back up the volume `data` nightly, encrypted, apart from the key secret (`docs/DEPLOY.md`, Keeping it).
6. The repository's variable `BITQUILT_TRACKERS` set to `https://tracker.bitquilt.org/`, which starts the mirror; the defaults in `packages/client/src/config.ts` and `scripts/build-mcpb.mjs` set to the same, then the release tag.

The house second opinion runs beside the tracker as two services from the same image, each with its own signing key: `house`, as an Anthropic model unless `HOUSE_VENDOR` says `openai`, and `house-openai`, as an OpenAI model. Each makes one pass, giving a second reading to pieces that have a reading on them, then waits `HOUSE_EVERY` seconds, 300 unless set; the compose file does not set it (`deploy/house.sh`). Neither takes an open piece (`docs/DEPLOY.md`, The house second opinion). Each runs nothing until its vendor's API key is set in `deploy/.env` and the service is brought up again, `ANTHROPIC_API_KEY` for `house` and `OPENAI_API_KEY` for `house-openai` (`docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d house house-openai`); `docker compose -f deploy/docker-compose.yml logs -f house` shows what the first did; `HOUSE=off` in the env file, and the same `up -d`, switches both off. Their signing keys live on the volumes `house` and `house_openai`.

Both doors are one program, `bitquilt-node` (`docs/DEPLOY.md`, Build and run): the public tracker is the node with the roles `admit,host` over the store the hosted tracker kept at `/data/tracker.db`, and the second door the node with `admit`; `QUILT_ROLES` in the compose file says which. The second peer runs on the same host under the same name (`docs/DEPLOY.md`, The second peer): the reference tracker alone as `tracker-two` at `/two/`, with a store of its own, and a Nostr relay of the host's own as `relay` at `/relay`, both handed their paths by Caddy, since the host's firewall admits 80 and 443 alone. The two doors name each other in `QUILT_PEERS` and fold each other's chains every five minutes (QX-21); `QUILT_RELAYS` gives the members' Quilts the relay to announce and search on. `curl -s https://tracker.bitquilt.org/two/.well-known/quilt` answers with the second door's name and its peer.

A new version: `git pull` and the same `up -d --build`; the volume stays. A change to the Caddyfile needs the Caddy container made again (`docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --force-recreate --no-deps caddy`): the file is bind-mounted by its inode, so after `git pull` replaces it a reload inside the container still reads the old one. The tracker refuses a problem whose challenge window is longer than `window_max_h` in the coin's parameters, and admits everything else the gate and the limits allow.
